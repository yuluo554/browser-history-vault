# 题目文档：浏览器历史本地知识库（browser-history-vault）

> **项目性质**：不参赛项目题（发布 GitHub **公开**仓库，署名 yuluo554）
> **目标产出**：`10-18-browser-history-vault`（浏览器历史本地知识库：90 天抢救 + 行为洞察）
> **版本史**：v1（2026-10-17 定稿；依据查证基准日 2026-10-17）；**v1.1（2026-10-17）**：§5 招牌动词表的命令名由 `vault` 改为 `bhvault`——避免与 HashiCorp Vault 的 CLI 同名互相遮蔽，其余不变。
> **交付形态（唯一）**：纯本地 Python CLI + 本地单文件 HTML 报告。无服务器、无 GPU、**零网络请求**、无账号、无云同步。
>
> **定位宣言**：浏览器只替你留 90 天历史，然后静默删除。本工具做「**先归档、再分析**」：首次运行即把本地 History 只读快照沉淀成自己的长期档案，之后回答「我过去在做什么」「哪些是遗忘的宝藏」「我的作息与兴趣怎么变」。**想法不空白、市场空白**——已有项目实现了清单里的功能却停在 3★，且它们都直接读浏览器、不解决 90 天蒸发问题。
>
> **品牌隔离与切割语**：本题只处理**浏览历史的时间序列与行为洞察**。不做书签整理、不做失效链接清理、不做页面内容存档。收藏是「打算以后看」，历史是「过去在做什么」——两者不是同一个问题，也不共用同一套判定标准。

## 1. 介绍

### 1.1 被静默删除的 90 天

Chromium 的历史记录不是永久资产，而是一个**滚动窗口**：

- **决定性限制（✅ 源码可证）**：Chromium 默认删除 **90 天**前的访问记录——`components/history/core/browser/history_backend.h` 中 `kExpireDaysThreshold = 90`；且过期清理时，若某 URL 已无剩余 visit，**连 URL 行本身也一并删除**（`expire_history_backend.cc`）。这意味着普通用户打开浏览器时能看到的，本质上只是「最近三个月」。
- **推论**：「遗忘的宝藏」「长期兴趣趋势」「年度回顾」这类问题，**在浏览器现库里根本回答不了**——不是算法不够好，是数据已经被删了。任何「直接读浏览器库」的工具都只能在同一个 90 天窗口里打转。
- **可选补源（✅ 路径存在）**：Google Takeout 可导出更长的历史，但依赖用户主动导出、格式与本地库不同，且不是所有浏览器都提供。
- **可行性（✅ 实测/源码可证）**：History 是**明文 SQLite**，时间戳为 **1601 纪元微秒**；Edge 同构。RyanDFIR/hindsight 与 joshuatownsend/chrome-history-explorer 均直接打开、无解密步骤。
- **运行中锁定（✅ 源码可证）**：浏览器运行时会锁库。可行做法是先把 `History` + `History-wal` + `History-shm` 复制到临时目录，再以读写模式打开让 WAL 折叠；参考实现见 `chrome-history-explorer/src/server/lib/sources/sqlite-open.ts`。另一条路线是 `sqlite3.backup()` 做一致性快照（keithah/browser-history 采用）。
- **隐私（✅ 设计前提）**：浏览历史是个人设备上最敏感的行为数据之一。必须只读副本、默认排除私密域名、报告本地生成、零网络请求。

### 1.3 已知竞品缺口（差异化依据）

3★ 的 chrome-history-explorer 功能覆盖很全，但存在四个明确缺口：

1. **直接读浏览器、不解决 90 天蒸发**——首次运行看到的就是残窗；
2. **无归档层**——没有自有长期库，无法跨时间累积；
3. **无中文场景报告**——中文域名/中文标题的分词、时区与作息解读缺失；
4. **无「档案可迁移/可增量合并」**——换机器、换浏览器无法把历史接上。

### 1.4 方法论与 AI 时代独特性拷问

为什么必须是工具而不是 LLM 聊天？

- **① 持久状态**：档案是跨月、跨年累积的本地状态，单轮聊天给不了，也不能替你保存；
- **② 进入既有工作流的交付物**：单文件 HTML 报告可直接归档、转发、留证，CSV 可进表格工具；
- **③ 可复现测量基建**：合成 History 库 + 植入真值 + 固定随机种子，任何人可一键复跑，数字不漂移。

「检查 + 报告」本身不算独特；独特的是**先抢救、再分析**这条不可逆的数据链，以及**每个数字可下钻回原始访问行**的可核验性。

## 2. 任务要求

首期限定 **5 个模块**，逐个交付，其余留扩展。每个模块遵守统一纪律：

- **只读纪律**：绝不写浏览器原库；所有读取都针对副本或自有档案库。
- **口径单一定义**：会话间隔、未访问天数 N、私密域名清单、聚类阈值等数值**只在配置文件一处定义**，代码、报告、文档均从该处取值，禁止第二份手写口径。
- **确定性纪律**：同一输入 + 同一配置 → 同一输出（字节级或结构化等价）；固定随机种子、确定性排序；不引入 LLM、不做隐式联网。
- **可下钻纪律**：报告中的每个聚合数字必须能追溯到原始访问行。

### 模块 ①：只读快照与归档层（M1）

- **输入**：Chrome / Edge 的本地 `History` 文件（含运行中场景的 `-wal` / `-shm`）。
- **输出**：自有归档 SQLite 库（独立于浏览器库）+ 本次归档的元数据（首次归档时间、覆盖区间、来源浏览器、新增/合并条数）。
- **做法**：
  1. 把 `History` + `History-wal` + `History-shm` **复制到临时目录**，再以读写模式打开让 WAL 折叠；
  2. `sqlite3.backup()` 作为兜底路径（适用于无法完整复制或需一致性快照的场景）；
  3. 增量合并进自有归档库，**`url_id` 稳定映射**（同一 URL 在多次归档中保持同一标识），visit 去重键为（url、visit_time、来源）。
- **确定性纪律**：合并顺序、去重键、ID 分配规则固定；重复归档同一份数据不产生重复行；原库 `mtime` 不变。
- **验收**：①浏览器运行中可用；②原库 `mtime` 归档前后不变；③归档库覆盖区间与缺口被如实记录；④重复归档幂等。

### 模块 ②：归档查询与全文检索（M2）

- **输入**：模块①的归档库。
- **输出**：按 URL / 标题 / 域名 / 时间范围的查询结果；CSV 导出。
- **做法**：查询直接基于自有库；中文检索采用分词或**字 n-gram 兜底**（不引入重型依赖，不依赖联网词典）。
- **确定性纪律**：排序键显式定义（如 visit_time 降序 + id 升序）；分页稳定；导出列顺序固定。
- **验收**：**断网可用**；同一查询重复执行结果一致；CSV 可被常见表格工具直接打开。

### 模块 ③：行为洞察报告（M3）

- **输入**：归档库 + 配置。
- **输出**：结构化洞察结果 + 进入 HTML 报告的数据块：
  - 访问频次榜（按 URL / 域名）；
  - 时段 / 星期热力（明确时区口径）；
  - 域名集中度；
  - 会话切分（**会话间隔 30 分钟**，定义在配置一处）；
  - **「遗忘的宝藏」**＝历史高价值但近 **N** 天未访问——**N 的定义只写在配置一处**，报告中显示实际取值。
- **确定性纪律**：聚合口径固定；并列名次用显式次排序键；报告中的每个数字可下钻到原始访问行。
- **验收**：每个数字可下钻；同一档案 + 同一配置重复生成，数字一致；N 改变时结果按定义变化且报告标注取值。

### 模块 ④：主题聚类与路径分析（M4）

- **输入**：归档库中的域名与标题词。
- **输出**：
  - 主题聚类（域名/标题词，规则或轻量 TF-IDF，**不引入重型依赖与 embedding 模型**）；
  - 研究路径（**同会话内连续跳转序列**，会话定义复用模块③的 30 分钟口径）。
- **确定性纪律**：**固定随机种子**（若算法含随机初始化）；聚类结果**确定性排序**（同分同序）；同一输入复跑结果一致。
- **验收**：聚类结果可复现；路径可下钻到具体 visit 序列；阈值取值在报告中可见。

### 模块 ⑤：隐私门禁与本地 HTML 报告（M5）

- **输入**：模块③④的输出 + 隐私配置。
- **输出**：**单文件 HTML 报告**（零外链、零网络请求、可离线打开）+ 隐私说明。
- **要求**：
  - 默认排除**私密域名清单**（清单只在配置一处定义）；
  - 敏感域名在报告中**自动打码**；
  - 首次运行**弹出隐私说明**（说明只读副本、本地生成、零上传）；
  - 报告与 README 必须显示**归档覆盖区间**与缺口提示（如「仅覆盖最近约 90 天」）；
  - 不上传任何数据，不内嵌远程字体/脚本/图片。
- **确定性纪律**：同一输入生成同一报告（内容层面）；渲染层不得引入新的判定逻辑。
- **验收**：断网打开报告功能完整；HTML 内无外部 URL 引用；覆盖区间与缺口提示存在；私密域名不出现在输出中。

- 国内浏览器（360 / QQ / 夸克）历史文件格式适配（⬜ 未验证）；
- Google Takeout 导入；

## 6. 边界与非目标

**不做（明确切割）**：

- **不写浏览器原库**——只读副本；任何情况下不得以写模式打开用户浏览器库；
- **不做书签整理**——书签是「打算以后看」，本题不处理收藏夹；
- **不做失效链接清理**——死链检测不在本题范围；
- **不做内容存档**——不抓取页面正文、不做全文快照；
