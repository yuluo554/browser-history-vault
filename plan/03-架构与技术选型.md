## 1. 形态与选型（结论 + 弃选理由）

| # | 决策 | 结论 | 弃选理由（要点） |
|---|---|---|---|
| A1 | 交付形态 | 纯本地 Python CLI + 本地单文件 HTML 报告 | 扩展拿不到完整字段与运行中 WAL；自托管服务与"最敏感行为数据不外置"冲突；桌面 GUI 不收敛会留空壳后门 |
| A2 | 核心链路 | **先归档、再分析** | 直接读浏览器库＝只看得到残窗（90 天蒸发）+ 运行中锁库 |
| A3 | 首期浏览器 | 仅 Chrome / Edge | 国内浏览器 / Firefox / Safari 格式 ⬜ 未验证，写成承诺即空头支票 |
| A4 | 检索范围 | 只针对归档库中的 URL / 标题 / 域名 | 不做页面内容索引/抓取（撞车已有大项目 + 显著扩大隐私与合规面） |
| A5 | 聚类算法 | 规则或轻量 TF-IDF（纯 Python） | 语义向量需 embedding 模型，违背"纯本地、轻量、零下载"，也让确定性复现复杂化 |
| A6 | 数值口径 | 全部进配置文件单一来源，**代码零默认值** | 代码默认值 = 配置改不动它；文档各写一份 = 必然漂移 |
| A7 | Python 底线 | **3.8+**（已在本机 3.8.8 与 3.12.10 双通道全量验证） | 本机可用通道恰为 3.8/3.12；把底线对齐到能真跑的通道，才谈得上"底线解释器跑过一遍"。零依赖使 3.8 兼容为零成本 |
| A8 | 配置文件格式 | **JSON**（`config.json` / `config.example.json`） | TOML 需 `tomllib`（3.11+）或第三方 `tomli`，与"零依赖 + 3.8 底线"冲突；JSON 是 stdlib。注释用 `_` 前缀键 |
| A9 | 时区口径 | **固定 UTC 偏移**（分钟，配置项） | 命名时区要 `zoneinfo`，而 **Windows 没有系统 tzdata**，零依赖下必然失败；且读系统时区会破坏"同一配置→同一输出" |
| A10 | 控制台命令名 | **`bhvault`** | `vault` 与 HashiCorp Vault 的 CLI 同名，安装即互相遮蔽；`python -m browser_history_vault` 作为等价通路 |
| A11 | 归档库引擎 | Python 标准库 `sqlite3`（SQLite ≥ 3.24 特性面） | 不引 ORM；不用 `RETURNING`（需 3.35+，而本机 3.8 通道自带 3.34.0） |
| A12 | 报告实现 | 单文件 HTML，内联 CSS/SVG，**无 JS 依赖** | 前端框架/CDN 与零外链硬约束冲突 |

   横切（全部模块共用，单点实现）：
     config.py  口径唯一来源（零默认值、显式解析链、打印生效来源）

**分层纪律**：

- **引擎层**（①–④）产出结论与结构化数据；**渲染层**（⑤）**只消费**，不重算任何判定（渲染层零判定是门禁项，不是自觉）；
- 所有写盘经同一个序列化入口（`K8`），不允许各子命令各写各的 `open()+json.dump()`；
- 数值/阈值一律从配置取，任何模块不得自带默认值。

## 3. 归档库 schema（M2 落地，此处定稿）

独立于浏览器库（`K10`）。四张表：

```sql
-- 来源浏览器的一次归档会话（每次 bhvault archive = 一行）
CREATE TABLE archives (
    archive_id     INTEGER PRIMARY KEY,          -- 自增
    source_browser TEXT    NOT NULL,             -- 'chrome' | 'edge'
    source_profile TEXT    NOT NULL DEFAULT '',  -- 语义性缺省用空串，不用 NULL（见下）
    started_at_us  INTEGER NOT NULL,             -- 1601 纪元微秒（注入时钟，非系统时钟）
    first_visit_us INTEGER NOT NULL,             -- 本次覆盖区间下界（无记录时哨兵）
    last_visit_us  INTEGER NOT NULL,             -- 本次覆盖区间上界
    visits_seen    INTEGER NOT NULL,             -- 本次扫描到的 visit 数（"我看了多少"）
    visits_added   INTEGER NOT NULL,             -- 本次实际写入的 visit 数（"我改了多少"）
    UNIQUE (source_browser, source_profile, started_at_us)
);

-- URL 维度：url_id 由本库稳定分配（K10）
CREATE TABLE urls (
    url_id        INTEGER PRIMARY KEY,           -- 稳定分配；不沿用浏览器 url_id
    url           TEXT    NOT NULL,
    title         TEXT    NOT NULL DEFAULT '',
    domain        TEXT    NOT NULL,
    first_seen_us INTEGER NOT NULL,
    UNIQUE (url)
);

-- visit 维度：去重键 =（url、visit_time、来源）
CREATE TABLE visits (
    visit_id       INTEGER PRIMARY KEY,
    url_id         INTEGER NOT NULL REFERENCES urls(url_id),
    visit_time_us  INTEGER NOT NULL,             -- 1601 纪元微秒
    transition     INTEGER NOT NULL DEFAULT -1,  -- 原库 transition 类型；未知用 -1
    source_browser TEXT    NOT NULL,
    source_profile TEXT    NOT NULL DEFAULT '',
    archive_id     INTEGER NOT NULL REFERENCES archives(archive_id),
    UNIQUE (url_id, visit_time_us, source_browser, source_profile)
);

-- 归档覆盖区间（可查"哪一段时间有数据、哪里是缺口"）
CREATE TABLE coverage (
    source_browser TEXT    NOT NULL,
    day            TEXT    NOT NULL,             -- 'YYYY-MM-DD'（口径时区下的一天）
    visits         INTEGER NOT NULL,
    PRIMARY KEY (source_browser, day)
);
```

**三条持久层纪律**：

1. **唯一键列不得为 NULL**：SQLite 唯一索引里 NULL 彼此不相等 → 重复入库会绕过唯一约束、幂等静默失效。因此"未知来源/未知档案"一律写**有值空串**（`''`），NULL 只留给"真的没有这一行"（实测踩坑：同一份报告重复入库却越长越长）；
2. **幂等判据不止"记录存在"**：归档的幂等 = 记录存在 **且** 与本地件的字节数/行数相符——只判存在会在数据被删/被截断时"永远认为已归档"（不重下也不报错）；
3. **`created_at` 类字段不读系统时钟**：由调用方注入（生产用系统时钟、测试与留档用固定值），否则"同输入双跑逐字节一致"在持久层失效。

## 4. 时间与纪元（`K11`）

- 浏览器时间戳是 **1601-01-01 UTC 起的微秒数**；转换只在 `timeutil` 一处实现（`us_to_datetime` / `datetime_to_us` + 常量 `EPOCH_1601`），**禁止在别处写魔数**；
- 展示层按配置的固定 UTC 偏移换算"本地时间"；星期/时段统计一律用该偏移下的本地时间；
- **排序键与聚合口径全程不读时钟**；"现在"由调用方注入（`now_us` 参数），保证可测试、可复现。

## 5. 只读快照流程（`K12`，模块①的核心）

```
1. 定位浏览器库目录（用户显式给 --browser-dir，或按平台候选路径探测；探测结果打印出来）
2. 只读检查：源文件存在？可读？浏览器可能正在运行（存在 -wal / -shm）
3. 复制到临时目录：History、History-wal（若有）、History-shm（若有）
     —— 原库只读：全程只 open('rb') / shutil.copyfile
4. 以读写模式打开**临时副本**（让 SQLite 折叠 WAL 到主库），或直接只读打开（wal 已折叠）
5. 兜底路径：若复制不完整或需一致性快照 → sqlite3.Connection.backup() 从只读连接打快照
6. 记录原库 mtime（归档前/后各取一次并比对；不一致即报错）
7. 从快照读出需要的列，交给归档器
```

**验收**：①浏览器运行中可用；②原库 `mtime` 归档前后不变；③覆盖区间与缺口如实记录；④重复归档幂等。

## 6. 确定性写盘（`K8`，全项目唯一口径）

所有机读产物统一走一个序列化入口：

| 项 | 固定值 | 理由 |
|---|---|---|
| 键序 | `sort_keys=True` | 字典迭代序不是契约 |
| 非 ASCII | `ensure_ascii=False` | 中文项目：`\uXXXX` 让 diff 不可读，与"人读产物"定位矛盾 |
| 缩进 | `indent=2` | 人读优先 |
| 行尾 | LF（`newline="\n"` / 字节写） | 跨平台"逐字节一致"的地基（Windows 默认 CRLF 会翻红） |
| 结尾 | 单个换行 | 无尾换行会让 diff 报 `\ No newline at end of file` |
| 编码 | UTF-8 | — |
| 写盘方式 | 写临时文件 → `os.replace`（原子写） | 中断不留半个产物 |
| 时钟字段 | 禁止入产物 | 破坏"同输入双跑一致" |

**机读载荷走字节写**（`K9`）：`bhvault config` / `selftest --json` 把 UTF-8 字节直接写 `sys.stdout.buffer`（无 buffer 时回落文本写），使输出不受控制台编码影响。

## 7. 配置：单点来源与解析链（`K2`/`K3`/`K4`/`K5`）

- **零默认值**：`VaultConfig` 的每个字段都必填；缺项/类型错/越界/未知键一律报错（退出码 2），错误信息点名缺的是哪一项。结构断言：任一字段出现默认值即测试变红；
- **解析链（显式登记，顺序固定）**：
  1. `--config <path>`（显式给出**只认它**；无效即退出码 2，**不回落其他来源**）；
  2. `<CWD>/config.json`；
  3. `<CWD>/config.example.json`；
  4. `<仓库根>/config.example.json`。
  找不到 → 退出码 2 并打印**探测过的全部路径**；
- **生效来源必须可见**：`config` / `selftest` 的输出里带 `_config_source` 绝对路径（"这份结论按哪份输入算的"必须可回答）；
- **`config_version` 升档判据**：**数据契约面**（字段集合/形态/口径语义）变了才升。只改代码与文档不升——按"改契约必须整目录重生成"的纪律，无信息量的升档会制造一次"所有产物都变了"的假信号；
- **配置键清单（生效口径全集）**：会话间隔、遗忘的宝藏三件套（未访问天数阈值 / 最少访问次数 / 最少跨越天数）、私密域名、敏感域名、时区偏移、随机种子、字 n-gram 的 n、聚类（min_df / max_features / top_terms / similarity_threshold）、报告（top_n / weekday_start）。键名与说明见 `config.example.json`（含 `_` 前缀注释）。

## 8. CLI 规格

```
bhvault [--version] <命令> [选项]

已交付：snapshot | archive | status | config | selftest
未交付（退出码 3，显式拒绝）：search | report | cluster
```

- 每个命令的 `--help` 必须能跑（有测试逐命令断言）；
- **参数面归属**：`--config` 只挂在已交付命令上；未就绪命令**不挂**——挂了却忽略它就是"参数被静默吞掉"，比报用法错误更坏。各模块落地时再随模块定义自己的参数（如 `--out-dir`）；
- **参数语义三条硬纪律**（后续实现必须遵守）：
  1. `or DEFAULT` 是错误写法——`--n 0` 这类合法 falsy 值会被静默改回默认；必须 `x if x is not None else D`；
  2. 装载产物按 `format` 字段**白名单分派**，未知 format 显式拒绝（防"喂错文件产出错结论"）；
  3. 多步链路的**每个中间产物都要落 `--out-dir` 可单步复查**（默认 `out/`，`.gitignore` 锚定），且"CLI 通路"与"直调编排函数"行为等价（三方对账）。

## 9. 包布局与安装面（`K18`）

```
src/browser_history_vault/     ← 唯一导入包（src layout）
  __init__.py                  ← 版本唯一来源（pyproject 以 dynamic 读取）
  __main__.py                  ← python -m 入口
  cli.py                       ← 参数解析、分派、退出码、编码守卫入口
  commands.py                  ← 命令登记表（CLI 与 selftest 共用的唯一来源）
  exit_codes.py                ← 退出码契约 + 未就绪登记表
  config.py                    ← 口径唯一来源 + 解析链 + 确定性序列化
  selftest.py                  ← 自检（逐项可证伪）
  netguard.py                  ← 零网络 import 守门（AST）
tools/                         ← 交付/审计脚本（**不属于用户 CLI**，见下）
tests/                         ← 测试（测试面 = 安装面 = README 指令面）
data/                          ← 台账 + 冻结 fixtures（**不进安装包**）
```

- **数据目录不进安装包**：本项目是**源码优先交付**（源码包 + editable 安装）；运行期数据经 `--data-root` / 仓库相对路径定位，实际用到的路径始终打印出来；
- **`tools/` 里的脚本是给我自己发版/验收用的，不做成用户子命令**（判据："这条命令是给用户用的，还是给我自己发版用的？"）。做成用户子命令会顺带把发布工具链发给用户、拖进零字面量门禁扫描面、并进冻结产物；
- **`python -m <pkg>` 与裸 `<pkg>` 是两条通路**（`sys.path` 来源不同）：CI 与冒烟脚本两条都跑，且 `--require-console-script` 让"console script 没进 PATH"变红而不是静默 SKIP；
- **版本四向一致**：`pyproject`（dynamic 读 `__version__`）/ `__init__.__version__` / git tag / README 状态行。

## 10. 零网络守门（`K17`）

"纯本地零上传"分四层审计，本阶段已落地两层，措辞与审计范围严格对齐：

| 层 | 手段 | 现状 |
|---|---|---|
| ① 源码 import 面 | AST 扫描（`import X` / `import X.Y` / `from X import Y` / `importlib.import_module("X")` / `__import__("X")` 逐形态；相对导入按所属包解析） | ✅ 已落地（`netguard.py` + 逐形态探针 + 阴性对照） |
| ② 发布产物扫描 | wheel/sdist 解包后扫第三方文件 | ⬜ 发布里程碑 |
| ③ 动态拦截 | socket 打补丁 + 全流程命令跑一遍零出网 | ✅ 已落地（测试内 socket 拦截；发布期补 netstat 旁证） |
| ④ 实际加载面 | `sys.modules` 导出后扫第三方文件 | ⬜ 发布里程碑 |

**措辞纪律**：四层全过才保留"零网络请求"的完整措辞；只做 ①③ 时，README 只能写"本项目代码不含任何网络调用路径"（当前 README 即按此措辞）。

## 11. 退出码退役流程（`K1` 配套）

未就绪退出码的触发点是 `exit_codes.STAGE_NOT_READY` 字典。某模块落地时**整项退役**，**五处同步**：

1. `STAGE_NOT_READY` 删条目；
2. CLI 分派接线改语义；
3. 面向用户文案（不得引用里程碑编号）；
4. 文档退出码表（README / plan/03 / plan/04）；
5. 测试改断言（含**防复活**负断言：`assert "snapshot" not in STAGE_NOT_READY`）。

**M2 已退役三条**：`snapshot` / `archive` / `status`。退役后剩余三条（`search` / `report` / `cluster`）
随模块②③④逐棒退役；五处同步的测试面同时包含**防复活负断言**
（`assert command not in STAGE_NOT_READY`）——否则"退役"会退化成"加了一条没人记得删的条目"。

**同步面 = 这个语义在仓库里的全部落点数**（本项目另加一处：决策记录，记"为什么删而不是留"）。
全部退役后 `EXIT_NOT_READY` 常量整项删除，不留恒不触发的死码——那会给后来者"这里还有未就绪语义"的假线索。
**逐阶段退役优于一次性退役**：每次退役都是一次真实接线改动，顺手同步成本最低。

## 13. 主要技术风险与对策

| 风险 | 触发场景 | 对策 |
|---|---|---|
| 运行中库被锁 → 读到不一致或不一致快照 | 浏览器正在运行 | 复制三文件 + 只在副本上折叠 WAL；`backup()` 兜底；一致性用行数/区间自检 |
| SQLite 文件字节跨平台不一致 | "合成库逐字节冻结"若直接对 `.db` 断言 | **冻结的是规范化导出**（JSONL 行集 + 结构计数），`.db` 只作可重建产物（见 plan/05） |
| 中文检索质量 | 无分词库 | 字 n-gram 兜底（n 取自配置），并诚实声明"非语义检索" |
| 聚类不可复现 | 随机初始化 | 固定种子（配置）+ 确定性排序；同分同序 |
| 报告泄私密域名 | 聚合与打码遗漏 | 门禁单点（排除 → 打码 → 渲染）；出口常驻断言 + 私密域名零出现测试 |
| 依赖环境差异（3.8/3.12、Windows/Linux） | 只有单一通道验证 | 本机双通道全量 + CI 四矩阵；底线解释器上跑新增守门 |
| 已交付命令的断言过期 | 里程碑推进改变退出码 | `K22`：交付同一次提交里退役旧断言并补离线冒烟 |
