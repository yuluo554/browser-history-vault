# 00 - README 总览：浏览器历史本地知识库（browser-history-vault）

**仓库**：`browser-history-vault`（GitHub 公开；本地工作目录名 `10-18-browser-history-vault`）
**性质**：不参赛项目题，发布 GitHub **公开**仓库，署名 yuluo554

## 2. 决策记录

> 说明：本节是**决策的历史记录**，其中的具体数字是设计期取值说明；**运行时生效口径一律以 `config.example.json` 为唯一来源**（见 §3 与 `plan/03` §12）。

### 2.1 题定稿期决策（v1，2026-10-17）

| # | 决策 | 备选方案 | 结论与弃选理由 |
|---|---|---|---|
| D1 | **形态 = 纯本地 Python CLI + 本地单文件 HTML 报告** | ①Chrome 扩展；②自托管 Web 服务；③桌面 GUI | **弃「扩展」**：扩展无法访问历史文件的完整字段与运行中 WAL 状态，且安装受企业策略限制；**弃「自托管服务」**：与「最敏感行为数据不上传/不外置」的隐私前提冲突；**弃「桌面 GUI」**：形态不收敛会留下空壳后门。CLI + 单文件报告是唯一形态 |
| D2 | **核心链路 = 先归档、再分析** | 直接读浏览器 `History` 做分析 | **弃「直接读浏览器库」**：①Chromium 默认 90 天过期（`kExpireDaysThreshold = 90`），首次运行只能看到残窗，长期洞察与遗忘宝藏失去数据基础；②浏览器运行中锁库，直接读易失败或不一致。改为只读副本 + WAL 折叠 + `sqlite3.backup()` 兜底 |
| D3 | **首期只做 Chrome / Edge** | 国内浏览器（360/QQ/夸克）纳入首期 | **弃「国内浏览器入首期」**：历史文件格式 ⬜ 未验证，写成承诺即为空头支票。降级为扩展项，文档标 ⬜ |
| D4 | **不做内容索引 / 全文抓取** | 抓取页面正文做全文搜索 | **弃「内容索引」**：与已有大项目（内容索引/搜索方向）正面撞车，且抓取正文显著扩大隐私与合规面。检索只针对归档库中的 URL/标题/域名 |
| D5 | **聚类 = 规则或轻量 TF-IDF** | 语义向量聚类（embedding） | **弃「语义向量聚类」**：需要 embedding 模型，违背「纯本地、轻量、零下载」前提，也让确定性复现变复杂。TF-IDF + 固定种子 + 确定性排序已足够首期 |
| D6 | **「遗忘的宝藏」的 N 等口径只在一处定义** | 代码内硬编码 + 文档各写一份 | 同源数字禁双写：N、会话间隔、私密域名清单、聚类阈值全部进配置文件单一来源，报告显示实际取值 |
| D7 | **不写会漂移的实现数字** | 题面写死测试数/行数/体积 | 数字会随实现漂移；只写口径与门槛来源，确需时以末态回填 |
| D8 | **隐私门禁为硬约束而非可选项** | 默认包含全部域名，用户自行过滤 | 浏览历史是最敏感行为数据；默认排除私密域名 + 自动打码 + 零外链 + 零上传为默认且不可静默关闭 |
| D9 | **报告必须显示覆盖区间与缺口** | 只显示分析结果 | 90 天窗口会让用户误以为「这就是我的全部历史」；覆盖区间与缺口提示是诚实性硬约束 |

**弃选项汇总（便于回访对照）**：直接读浏览器库（90 天蒸发 + 锁文件）、国内浏览器入首期（格式 ⬜ 未验证）、内容索引/全文抓取（撞车 + 隐私）、语义向量聚类（需 embedding 模型，违背纯本地轻量）。

### 2.2 骨架期决策（v1 → v2，2026-10-17）

| # | 决策 | 备选方案 | 结论与理由 |
|---|---|---|---|
| D10 | 运行时**零第三方依赖**（stdlib only） | 引入 pandas / jieba / scikit-learn | 零依赖是「下载即用 + 可审计」的定位前提；中文检索用字 n-gram 兜底，聚类用纯 Python TF-IDF |
| D11 | 归档库独立于浏览器库 | 原地加表 | 原库只读是红线；独立库才能承载跨浏览器、跨设备的增量合并 |
| D12 | visit 去重键 =（url、visit_time、来源浏览器、来源 profile） | 仅 visit_time | 不同浏览器可能在同一微秒有不同访问；加入来源避免误去重。唯一键列**不得为 NULL**（用 `''` 哨兵，否则幂等静默失效） |
| D13 | `url_id` 由归档库稳定分配 | 沿用浏览器 url_id | 浏览器清理会删 URL 行并复用 id；沿用会导致档案内 ID 漂移 |
| D14 | 报告静态生成，无 JS 依赖也可读 | 前端框架 + 图表库 CDN | 零外链硬约束；图表用内联 SVG/CSS 实现 |
| D15 | 里程碑 M1 数据先行 | 先写 CLI 再补数据 | 合成 History 库 + 植入真值是所有后续断言的地基；先做数据可避免「口径无真值可验」 |
| **D16** | **Python 底线 = 3.8+**（原 D10 写作 3.9） | 保持 3.9 底线 | 本机可用通道恰为 3.8.8 与 3.12.10——把底线对齐到**能真跑的通道**，才谈得上"新增守门用底线解释器跑一遍"。零依赖使 3.8 兼容零成本（仅需避开 3.9+/3.10+ API）。实测已抓到一处：`Path.write_text(newline=)` 是 3.10+ 参数，3.12 全绿而 3.8 必红 |
| **D17** | **配置格式 = JSON**（`config.json` / `config.example.json`） | TOML / INI / YAML | TOML 需 `tomllib`（3.11+）或第三方 `tomli`，与「零依赖 + 3.8 底线」冲突；JSON 是 stdlib。注释用 `_` 前缀键 |
| **D18** | **时区口径 = 固定 UTC 偏移**（分钟） | 命名时区（`zoneinfo`） | Windows **没有系统 tzdata**，零依赖下 `ZoneInfo` 必然失败；且读系统时区会破坏「同一配置 → 同一输出」。固定偏移同时解决问题与确定性 |
| **D19** | **控制台命令名 = `bhvault`**（题面 §5 表同步为 v1.1） | 保持 `vault` | `vault` 与 HashiCorp Vault 的 CLI 同名，安装即互相遮蔽。`python -m browser_history_vault` 作为等价通路 |
| **D20** | **未交付命令用退出码 3 显式拒绝**（不伪造空结果） | 打印"未实现"后返回 0 / 静默忽略 | 「命令跑通 ≠ 命令做对了」：空壳 `return 0` 会让所有门死绿。未就绪拒绝**不读配置、不写任何文件**，面向用户文案**不引用里程碑编号** |
| **D21** | **`tools/` 是交付/审计脚本，不做成用户子命令** | 把发布/基准工具挂进 CLI | 判据："这条命令是给用户用的，还是给我自己发版用的？"——后者挂进 CLI 会随包发给用户、被拖进零字面量门禁扫描面、并进冻结产物 |
| **D22** | **零网络守门先落两层（①源码 import 面 + ③运行时拦截），措辞同步收敛** | 直接写"零网络请求" | 「只扫本项目源码不足以支撑零网络调用措辞」——README 写"本项目代码不含任何网络调用路径"，四层全过再升级措辞（`plan/03` §10） |
| **D23** | **发布终态门禁（`tools/check_release.py`）刻意不进 CI** | 挂进 CI 一起跑 | 判据："这道门在当前时点本来就该红吗"——tag/Release 未建时它必然红，挂 CI 只会让正常提交红得没有信息量。它的可跑性与可证伪性由 `tests/test_release_gate.py` 覆盖 |
| **D24** | **本阶段不预置空跑的生成器与基准** | 先把 `tools/bench.py` 与空 fixtures 建起来 | 空分母会伪装成"通过"；`not_enabled` 与"跑了没过"必须可区分。M1 数据先行时一并落地（`plan/05` §11） |
| **D25** | **`config_version` 只在数据契约面变化时升档** | 每过一个里程碑升一档 | 无信息量的升档会制造一次"所有产物都变了"的假信号，白掉全部冻结字节。本阶段把遗忘的宝藏三件套一次定进契约（新增 3 个必需键），因此**不预留后续升档** |

### 2.3 M1 数据先行期决策（v2 → v3，2026-10-17）

| # | 决策 | 备选方案 | 结论与理由 |
|---|---|---|---|
| **D26** | **WAL 变体单独放 `chrome-running/` 目录**（而非与干净库同目录的 `chrome/History` + `chrome/History-wal`） | 按 M0 的目录草图把两者并列 `chrome/` | WAL 必须与自己的主库**同名同目录**（SQLite 语义）：一个目录里同时放"干净库"和"另一条 WAL"在语义上不成立，读 `chrome/History` 会变成"到底折没折 WAL"说不清。因此干净库 `chrome/`、运行中库 `chrome-running/`、第二来源 `edge/` 各一份 |
| **D27** | **标题是 URL 维度**（同 URL 的多次访问标题恒定） | 每次访问各带标题 | 真实库的 `urls.title` 是**一条 URL 一行**。生成期就让同一 URL 的标题一致（否则写进库只剩一个，"读回的导出"必然与冻结导出不符——实测踩到，报错位置还离原因很远）。这条不变量在生成期显式校验 |
| **D28** | **参照实现放包内**（`reference.py`），生产模块禁止 import | 放 `tools/` 或只放测试里 | `plan/05` §7 的三条落点位：放包内（装好的包也有它）/不共享（否则真值 = 引擎自证）/必被真命令读（`selftest` 与 `bench` 真读）。三条都由 AST 守门（`tests/test_reference_isolation.py`）钉死，白名单式（新模块默认禁止） |
| **D29** | **`timeutil` 提前到 M1 落地** | 等 M2 随模块①再建 | K11 要求"1601 转换只在 timeutil 一处"，而 M1 的真值与生成器都要算时间；先落单点比事后收敛便宜。它同时是生成侧"同口径独立实现"的对撞对象 |
| **D30** | **生成器 sha256 进台账**（改了生成器就要重生成） | 只登记数据产物的 sha256 | 台账要能回答"这批数据是哪份生成器产出的"。代价是"改一行注释也要重生成"，而这是**收益**：把"改了生成器没重生成数据"从静默漂移变成一次显式动作（实测：本棒的每次生成器改动都如期把 `--check` 打红） |
| **D31** | **`config.example.json` 的私密/敏感清单各加一个保留域示例项** | 真值改用真实域名样本 / 另建一份基准配置 | 合成库只许用保留域（D 级纪律），而"默认排除 + 子域一并排除"与"敏感打码"这两条口径必须**在自带数据上可复跑验证**。加两个保留域示例项比"再维护一份基准配置"少一处口径分叉；对真实用户无影响（不存在这样的站点），且注释里写明可删 |
| **D32** | **基准加 B0 套件**（数据底座与真值一致性） | 本棒只登记 B1–B5 为未启用、不跑任何套件 | 未启用套件按设计计入退出码 1，若一个都不启用则"基准骨架"没有任何东西被真跑过——门是空的。B0 只依赖数据、不依赖引擎，正好是本阶段能真跑的那一个（真值可由独立参照实现复算） |

### 2.4 M2 归档期决策（v3 → v4，2026-10-18）

| # | 决策 | 备选方案 | 结论与理由 |
|---|---|---|---|
| **D33** | **退役 `snapshot` / `archive` / `status` 三条未就绪条目**（不是"留着但接线"） | 保留条目、只在 CLI 里先分派 | 条目留着会让 `--help` 的分组、面向用户文案与测试断言继续把已交付能力说成"未交付"；五处同步（`exit_codes.py` / CLI 分派 / 面向用户文案 / README 退出码表 / 测试含**防复活**负断言）是"退役"的定义。**剩余三条**（`search`/`report`/`cluster`）随模块②③④逐棒退役；全部退役后才删 `EXIT_NOT_READY` 常量 |
| **D34** | **归档库保留全量记录；私密域名在"输出面"生效** | 入库前就过滤掉私密域名 | 两条硬证据否掉了"入库前过滤"：①`assumptions/archive_idempotence.json` 冻结的期望是首跑 `visits_added == 367`（=全量）；②归档库是用户自己的长期档案，入库前删掉会让"以后改了清单也找不回那些记录"。K26 约束的是**输出面**（报告 / CSV / 导出 / 打印），因此：归档库留全量 + `archives.private_records_seen` 如实计数 + `--out-dir` 的规范化导出**过门禁**（`privacy.keep_visible` 单点）。M5 的报告门禁消费同一份 `privacy.py` |
| **D35** | **快照路径上绝不用 SQLite 打开源库（连 `mode=ro` 也不行）** | 直接只读打开源库取快照 | 实测：WAL 模式的库被打开时 SQLite 需要 `-shm` 共享内存索引；源目录没有它时会**在源目录里创建**（本次实测：`chrome-running/History-shm` 凭空出现）。这直接破坏"原库零写入"红线。因此顺序固定为"先按字节复制（源侧只 `open('rb')`）→ 只在副本上用 SQLite"。`backup()` 兜底也从副本读，不从源库读 |
| **D36** | **`-shm` 不参与"源库未被改动"的字节比对** | 三文件（History / -wal / -shm）一起比 | `-shm` 是 WAL 的共享内存索引，浏览器在跑时内容每个瞬间都在变。拿它做"字节没变"的判据会**恒红**，于是这条门会被当成噪音关掉——比没有门更糟。它仍被记录（是"浏览器在运行"的信号），只是不参与字节比对 |
| **D37** | **规范化器的重复去重键：生产侧"确定性保留 + 显式计数"，对撞侧报错** | 一律报错 / 一律静默去重 | 实测：本机真实 Chrome 库**确实存在**同一 `(visit_time, url)` 的多条 visit。一律报错会让"归档真实数据"不可用；静默丢弃会让"到底存了哪一条"说不清。因此 `on_duplicate="dedupe"`（保留规范序第一条 + 返回被合并数）为生产默认，`on_duplicate="error"` 用于冻结 fixtures 对撞（数据底座出现重复键意味着生成侧口径坏了，不能被"去重"掩盖） |
| **D38** | **B1 探活打在"实现"上，B0 探活打在"数据"上** | 两套都用数据变异 | 只打数据会漏掉"代码写错但数据没动"的形态（例如幂等计数谎报、覆盖计数不落库）。B1 的三条探活分别注入：计数谎报 / 覆盖不落库 / 快照顺手改源库；每条都在 `finally` 里还原（含 mtime），并由 `test_bench_leaves_the_fixture_untouched` 连 mtime 一起断言 |
| **D39** | **测试与冒烟的"浏览器探测"必须隔离 HOME** | 直接跑 `snapshot` 看退出码 | 实测：不隔离时 `snapshot` 会真的探测到本机 Chrome 目录并**读用户的真实浏览历史**。因此测试/冒烟一律把 `HOME`/`USERPROFILE`/`LOCALAPPDATA`/`APPDATA` 指向临时目录，`candidate_dirs(home=...)` 也据此**完全**从该 home 派生（连环境变量都不读） |
