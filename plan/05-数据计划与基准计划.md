# 05 - 数据计划与基准计划

> 上游：`plan/03-架构与技术选型.md`（K 清单）、`plan/04-模块详设.md`（各模块验收判据）。
> 本计划的核心资产不是代码，而是**程序化自制、带植入真值、可一键复跑**的合成浏览历史数据集——
> 它让"归档幂等 / 口径正确 / 聚类可复现 / 隐私门禁"这些承诺从口头声明变成**可复跑的测量**。
> **本阶段（M0）只落计划，数据与基准在 M1 落库**（不预置空跑的生成器与基准——空分母会伪装成"通过"）。

---

## 1. 为什么必须自制数据

真实浏览历史有三重不可用：**隐私**（本人最敏感的行为数据，绝不入仓）、**不可复现**（每个人的库都不同，且浏览器在滚动删除）、**无真值**（没有任何标注告诉我们"哪条该被判定为遗忘的宝藏"）。

因此本项目的数据底座 = **程序化生成的合成 History 库 + 显式植入的真值**：

- 合成库只使用**保留域名**（假域名白名单），可安全入仓；
- 植入真值让每个判定口径都有**可打红的期望**；
- 固定种子 + 确定性生成，让任何人（包括 CI）一键复跑，数字不漂移。

## 2. 数据目录结构（M1 落地）

```
data/
  README.md                         # 台账：查证记录、数据源可获取性、合成纪律、数值口径纪律（✅ 已存在）
  fixtures/
    synthetic/
      manifest.json                 # 生成清单：种子、记录数、覆盖区间、门槛、各产物 sha256、fail-closed 状态
      canonical/
        visits.jsonl                # 规范化导出（**逐字节冻结**的比对对象）
        counts.json                 # 结构计数（各表行数、按来源/按日分布）
      chrome/
        History                     # 合成 Chrome 库（假域名；供快照/归档模块吃）
        History-wal                 # 合成 WAL（用于验证"运行中锁库"路径）
      assumptions/                  # 各模块的"输入 → 期望"真值（只存输入与期望）
        sessions.json
        forgotten.json
        heatmap.json
        domains.json
        topics.json
        paths.json
        search.json
        privacy.json
        archive_idempotence.json
```

生成器：`tools/gen_synthetic_history.py`（`--out data/fixtures/synthetic`、`--check`、`--seed <固定>`）。

## 3. 合成纪律（继承并细化 `data/README.md` §3）

1. **假域名白名单**：仅用 RFC 2606 / RFC 6761 保留域（`example.invalid`、`example.test`、`example.*`）；
   禁止任何真实站点域名、真实用户名、真实邮箱；标题用中性占位文本（如「示例文章 A-001」）。
2. **真值显式登记**：每条植入事实写进 `assumptions/*.json` 的"输入 + 期望"记录，并在 `manifest.json` 登记计数与 sha256。
3. **时间**：时间戳按 1601 纪元微秒写入（生成器内部走与生产代码**同一份转换口径**的独立实现，见 §6）；
   测试与断言使用**相对时间**（如"最后访问距归档基准日 N+1 天"），不写死日历日期。
4. **私密域名样本必须存在**：真值里要有一批私密域名访问，用来验证"零出现"。
5. **真实历史永不入仓**；`.gitignore` 已封死 `History*` / `*.db` / 报告产物。

## 4. 植入真值清单（M1 交付物的核心）

| 真值文件 | 植入的输入 | 期望（可由输入独立复算） | 消费方 |
|---|---|---|---|
| `archive_idempotence.json` | 同一快照连跑两次 | 第二次 `visits_added = 0`；行数与 ID 映射不变 | 模块① |
| `sessions.json` | 刻意构造的三态间隔（恰好等于配置间隔 / 少 1 秒 / 多 1 秒） | 会话切分结果（边界不切分） | 模块③ |
| `forgotten.json` | 刻意构造的 URL 组：满足三条件的、只差一天的、访问次数不足的、跨越天数不足的、在私密清单里的 | 命中集合与逐条理由 | 模块③ |
| `heatmap.json` | 指定偏移下的访问分布（含跨日样本） | 24×7 桶计数 | 模块③ |
| `domains.json` | 指定域名的访问比例 | 占比与分母 | 模块③ |
| `topics.json` | 指定标题词族分布 | 固定种子下的分组结果 | 模块④ |
| `paths.json` | 同会话内连续跳转序列（含跨会话反例） | 路径步骤序列 | 模块④ |
| `search.json` | 含中文标题的样本 | 字 n-gram 查询命中集合 | 模块② |
| `privacy.json` | 私密/敏感域名访问 | 报告中零出现 / 打码形态 | 模块⑤ |

**真值语义纪律（三条，全部要有测试或门禁）**：

1. **真值库只存"输入与期望"**：不得出现 `observed_*` 一类字段——冻结"观测"会让基准退化成"比对两份预先算好的答案"，引擎整体失效也照样全绿。判据：真值库里出现 `observed` 即红；
2. **期望值必须可由输入独立复算**：把引擎实现注释掉，真值仍能算出来（否则期望值与引擎同源 = 引擎自证）。因此真值记录里写的是**规则谓词 + 参数**，评测时由独立的参照实现复算；
3. **必含反例样本**："看起来像但没命中"的项必须有（例如访问次数刚好差一次、间隔刚好差一秒、域名是私密的）——只测"该命中的命中了"，口径写反永远不会红。

## 5. 门禁门槛随数据下发（不写进代码）

`manifest.json` 携带各套件的门槛（`min_detection_rate`、`max_false_positive`、`min_samples_per_kind` 等），
**基准运行时从 manifest 读门槛**（数据非代码）：改门槛是改数据 + 重生成，不需要改代码，也留痕。

同时登记**覆盖声明**（总数 / 采样数双列）：每个真值类别登记"该类别样本总数"与"本次抽样/生成数"，
并显式写出"抽样覆盖非穷举"——否则"每类都有样本"会被读成"全穷举"。

## 6. 确定性生成纪律（假门的头号来源）

1. **禁 stdlib `random`**：自研确定性 RNG（如 splitmix64），序列不依赖 Python 版本；
2. **禁 `set` 迭代序、禁系统时钟、禁文件枚举序**：所有顺序来自显式排序键；
3. **落盘产物无时间戳字段**；
4. **`--check` 两层断言**（只断言一层是经典假门）：
   - 第一层：**冻结产物自身形态正确**（结构计数、真值库无 `observed_*`、白名单域名校验）；
   - 第二层：**重跑生成器到临时目录 → 与冻结产物逐字节比对**。
   变异验证：把生成器改坏（如把"私密域名"样本洗白）→ 两层里至少一层必须变红。
5. **字节冻结的分层设防**（不同产物类型各审一遍）：

| 产物 | 冻结方式 | 说明 |
|---|---|---|
| 文本类（JSONL / JSON / manifest） | 行尾 LF + 键排序 + 结尾换行；`--check` 逐字节比对 | 文本行尾守门已有（`tests/test_line_endings.py`） |
| `canonical/visits.jsonl` | **这是逐字节冻结的对象** | 规范化导出，不含任何平台相关元数据 |
| `chrome/History`（SQLite） | **可重建产物，不作逐字节冻结对象** | SQLite 文件字节不承诺跨平台/跨版本一致；`--check` 比的是"导出是否一致" |
| 未来若引入 zip 容器 | `ZIP_STORED` + `create_system=0` + 固定 `date_time` | 否则 deflate 流与宿主标识会让字节漂移 |

**规范化序单点定义，且生成侧与生产侧各一份独立实现**（一致性靠逐字节测试守门，**别顺手统一成一个 import**——统一后生成侧就变成"用被测实现生成期望"，真值失去独立性）。

## 7. 基准套件（M1 起逐个落地）

| 套件 | 测什么 | 样本驱动层 | 规则驱动层（不读真值库，专治"样本没覆盖的端点"） |
|---|---|---|---|
| **B1 归档幂等** | 只读 + 幂等 + ID 稳定 | 同一快照双跑、运行中带 `-wal` 场景 | 构造"重排输入顺序 / 分批归档 / 归档中断后续跑"的规则用例 |
| **B2 查询确定性** | 排序键、分页、CSV | 真值查询用例 | 随机生成查询参数组合，断言"两次执行逐字段一致" |
| **B3 洞察口径** | 会话边界、遗忘宝藏、热力、集中度 | 真值命中（逐样本点名） | 边界推导：间隔 ±1 秒、天数 ±1 天、分母为空/为 1 |
| **B4 聚类与路径** | 复跑一致、同分同序、路径序列 | 真值分组 | 构造并列分值样本，断言次序由显式次排序键决定 |
| **B5 隐私与零外链** | 私密零出现、打码、零外链 | 真值隐私样本 | 注入伪造的私密域名到各通路（标题/域名/CSV/HTML），断言零出现 |

**基准门是"双边"的**（只守误报率会让引擎整体失效时照样全绿）：

1. **误报率 0**：真值为"不应命中"的样本一条都不许命中；
2. **检出率 ≥ 门槛**：真值为"应命中"的样本必须被检出，且**逐样本点名**（差异落到具体样本 id，防汇总率掩盖"某类全零"）；
3. **逐类覆盖达 `min_required`**：每个真值类别的样本数不低于门槛；
4. **错误类型归属逐样本核对**：不能只查"是否判定命中"（"任意一类命中就宣称检出"会蒙混过关）。

**每套件配可证伪探活**：注入一个已知缺陷（从实算值派生，不写死），基准**必须报未达标**；
探活要打在**消费处**（真被命令/基准读到的那个导入引用），打在定义处不生效。
**参照实现的三个落点位**：放**包内**（否则装好的包里没有它）/**不共享**（生产模块禁止 import 它，配 AST 守门）/**必被真命令读**（不能只在测试里被调用）。

**"整套件数据缺失"与"跑了没过"必须可区分**：空分母不得冒充通过——`not_enabled=true` + notes 声明 + 退出码 1。

## 8. 冻结台账必须被"用户敲的那条命令"真读

`manifest.json` 不只是测试的输入：**`bhvault selftest --data-root data` 必须真读它**（校验行数、区间、
各产物 sha256 与盘上一致），否则"台账冻结"只是测试内部的事，用户那条命令照样能全绿跑过一份被改坏的 fixtures。

落地：M1 把 `data/fixtures/synthetic/manifest.json` 加入 `selftest.REQUIRED_DATA_ASSETS`
（`src/browser_history_vault/selftest.py`）并加对应检查项——**这是"动了会打挂测试"的口径变更**，
须同步 `plan/03` K 清单、`plan/05` 本文档与 selftest 测试三处。

## 9. 计数口径与恒等式

- 汇总行先标注单位：`visits_seen`（本次扫描）/ `visits_added`（本次写入）/ `urls`（条目数）/ `visits`（记录数）；
- 增量幂等的第二次运行必须**计数归零**（不是"没报错"）：`visits_added == 0`；
- 命中类恒等式写成**集合划分**（`命中条目 ∪ 剔除条目 ∪ 零命中条目 == 全部条目`，三者互不相交），不写加法。

## 10. 基准退出码与命令面

`tools/bench.py`（dev 工具，**不做成用户子命令**）：

```
tools/bench.py [--suite B1 B2 ...] [--only <suite>] [--json] [--out-dir out/]
退出码：0 = 全部达标 / 1 = 有未达标或 not_enabled / 2 = 用法与未知名错误
```

- 新增套件必须注册进 `--only` 白名单（防"新套件没被任何东西跑到"）；
- CI 在 M1 起加一步跑全部套件（离线、不联网）；
- **"未启用"不冒充通过**：`not_enabled` 与"跑了没过"同码不同义，文本可区分。
