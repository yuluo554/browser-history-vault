# 04 - 模块详设（接口 / 判定语义 / 验收判据）

> 上游：`plan/03-架构与技术选型.md`（§12 的 K 清单是本文档的约束）。
> **数值口径一律取自 `config.example.json`**，本文档只写键名与判定语义，不复述数值。
> 每个模块的接口都是"纯函数 + 不可变 dataclass"风格：不读全局、不读时钟（"现在"由调用方注入）、不写盘（写盘经统一序列化入口）。

---

## 0. 跨模块通用约定

| 约定 | 内容 |
|---|---|
| 记录契约 | 归档后的最小记录：`VisitView(url_id, url, title, domain, visit_time_us, source_browser, source_profile, visit_id)`；`evidence` 字段携带 `visit_id` 供下钻 |
| 时钟 | 所有"当前时间"由参数注入（`now_us`）；模块内部**禁止**读 `time.time()` / `datetime.now()` |
| 随机 | 只用配置里的固定种子；禁 stdlib `random` 的跨版本序列承诺（自研确定性 RNG，见 plan/05） |
| 写盘 | 一律经统一序列化入口（K8）；产物落 `--out-dir`，可单步复查（K20） |
| 隐私 | 记录进入任何聚合之前先过门禁单点（K26）；模块②③④不得各自实现过滤 |
| 下钻 | 每个聚合数字必须带可解析的引用（`visit_id` 列表或可复算的谓词） |
| 计数 | 汇总行标注单位：条目数 / 记录数、本次写入 / 本次扫描（K21） |

## 模块① 只读快照与归档层（`snapshot` / `archive`）

### 接口

```python
@dataclass(frozen=True)
class BrowserSource:
    key: str                 # 'chrome' | 'edge'
    browser_dir: Path        # 用户显式给出或探测得到（探测结果必须打印）
    history_file: Path
    wal_file: Path | None
    shm_file: Path | None

@dataclass(frozen=True)
class SnapshotHandle:
    tmp_dir: Path            # 临时目录（用完即删；不留残留）
    db_path: Path            # 折叠 WAL 后的副本
    source_key: str
    source_mtime_ns: int     # 归档前原库 mtime（用于归档后比对）
    copied_files: tuple[str, ...]

def detect_sources(explicit_dir: str | None) -> list[BrowserSource]: ...
def take_snapshot(source: BrowserSource, tmp_root: Path) -> SnapshotHandle: ...
def read_visits(handle: SnapshotHandle) -> Iterator[VisitView]: ...
def archive_snapshot(handle: SnapshotHandle, archive_db: Path, *, now_us: int) -> ArchiveResult: ...
```

### 判定语义与做法

1. **只读**：源文件全程只 `open('rb')` / `shutil.copyfile`；**绝不**以写模式打开用户原库（K12）；
2. 复制 `History` + `History-wal` + `History-shm` 到临时目录 → 在**副本**上以读写模式打开让 WAL 折叠；
3. 兜底路径：复制不完整或需一致性快照 → `sqlite3.Connection.backup()`；
4. `url_id` **由归档库稳定分配**（不沿用浏览器 `url_id`：浏览器清理会删 URL 行并复用 id，沿用会让档案内 ID 漂移）；
5. visit 去重键 =（url、visit_time、来源浏览器、来源 profile）；唯一键列用**有值空串**而非 NULL（K10）；
6. 归档元数据：首次归档时间、覆盖区间（`first/last_visit_us`）、来源浏览器、本次 `visits_seen` / `visits_added`（K21 的"看了多少 / 改了多少"两轴）；
7. 归档完成后**再取一次原库 `mtime`** 并比对；不一致 → 报错（不是警告）。

### 验收判据

| 判据 | 断言形态 |
|---|---|
| 浏览器运行中可用 | 合成带 `-wal` 的库 + 模拟锁场景，快照能取到记录 |
| 原库零写入 | 归档前后源文件 `mtime` + 字节 sha256 均不变 |
| 增量幂等 | 同一份快照连跑两次：`visits` 行数不变，`visits_added` 第二次为 0 |
| `url_id` 稳定 | 两次归档后同一 URL 的 `url_id` 相同 |
| 覆盖区间如实 | 缺口区间与合成真值一致；`status` 输出含区间与缺口 |
| 只读副本 | 源库文件在快照后未被修改（字节级比对） |

## 模块② 归档查询与全文检索（`search`）

### 接口

```python
@dataclass(frozen=True)
class SearchQuery:
    text: str | None = None          # 匹配 URL / 标题（中文走字 n-gram 兜底）
    domain: str | None = None
    since_us: int | None = None
    until_us: int | None = None
    limit: int | None = None
    offset: int = 0
    order: str = "visit_time_desc"   # 显式排序键白名单

@dataclass(frozen=True)
class SearchHit:
    visit_id: int
    url: str
    title: str
    domain: str
    visit_time_us: int

def search(archive_db: Path, query: SearchQuery, *, config) -> list[SearchHit]: ...
def export_csv(hits: Iterable[SearchHit], out_path: Path) -> ExportSummary: ...
```

### 判定语义

- **排序键显式定义**：`visit_time_us` 降序 + `visit_id` 升序（并列名次必有次排序键，否则分页不稳定）；
- **分页稳定**：`limit/offset` 在同一排序键下可重复复现；
- **中文兜底**：把查询串与标题都切成**字 n-gram**（n 取自配置）做包含匹配——**不引入分词库、不联网词典**；命中语义是"子串级"而非"语义级"，报告与 README 必须如实声明这一点；
- **CSV**：列顺序固定（`visit_id, visit_time_local, url, title, domain, source_browser`），`newline=""` 打开、UTF-8（可选 BOM 由显式开关决定，默认不加）；导出即写盘 → 经统一序列化/写盘入口；
- **导出必须过隐私门禁**：私密域名记录在导出中同样零出现。

### 验收判据

| 判据 | 断言形态 |
|---|---|
| 断网可用 | 测试环境无网络依赖即可通过（并配 socket 拦截跑一遍） |
| 重复查询一致 | 同查询两次执行结果逐字段一致（含分页） |
| 中文命中 | 含中文标题的合成样本可被字 n-gram 查询命中（真值用例） |
| 排序确定 | 打乱输入顺序后结果一致（顺序不由容器物理序决定） |
| CSV 可打开 | 列序固定 + 行数对账 + 用 `csv` 模块读回逐条比对 |

> **M3 落地形态**（口径与上面一致，只补充"实现落在哪、边界怎么定的"）：
>
> - 实现落在 `src/browser_history_vault/search.py`：`SearchQuery`（值对象）→ `run_search`（纯函数，
>   只对**已过门禁**的行工作）→ `search_rows`（**带门禁的入口**，CLI / 基准 / 测试都走它：
>   把 `privacy.keep_visible` 与检索绑在一个函数里，调用方少写一行就漏掉整条隐私约束）。
>   数据来自 `storage.visit_view_rows`（在 `CANONICAL_FIELDS` 之上补 `visit_id` / `url_id` 供下钻）。
> - 排序键白名单只有 `visit_time_desc` = `(visit_time_us 降序, visit_id 升序)`；未知取值**拒绝**（不回落默认）。
> - 命中语义实现为"查询的全部 n-gram ⊆ 目标的 n-gram 集合"，**大小写按 `casefold` 处理**
>   （真值只冻结"两种读法结论一致"的用例，因此 casefold 不是被真值钉死的口径，这里显式声明并
>   由 `tests/test_search_command.py` 与参照实现按同一取值对账）。
> - `--domain` 与私密清单**共用同一套匹配语义**（`privacy.host_matches_entry`：等于或为其子域）；
>   `--since-us/--until-us` 是**闭区间**；`offset` 超出末尾返回空集而不是报错。
> - CSV 落 `<out-dir>/search.csv`（列序固定、UTF-8 无 BOM、LF、原子写 `serialize.write_bytes_atomic`），
>   机读载荷落 `<out-dir>/search.json`；**URL 列与标题列也过 `privacy.redact_text`**
>   （只掩码域名列会让原主机名从 URL 里漏出去）。

## 模块③ 行为洞察（`report` 的数据层）

### 接口

```python
@dataclass(frozen=True)
class InsightBundle:
    coverage: CoverageInfo        # 覆盖区间 + 缺口
    top_urls: list[RankedItem]
    top_domains: list[RankedItem]
    heatmap: HeatMatrix           # 24 小时 × 7 天（口径时区下的本地时间）
    sessions: list[SessionInfo]
    forgotten: list[ForgottenItem]
    effective_config: dict        # 报告必须显示实际生效口径（K14）

def build_insight(archive_db: Path, *, config, now_us: int) -> InsightBundle: ...
```

### 判定语义（每条都能被真值打红）

| 区块 | 定义 | 边界与陷阱 |
|---|---|---|
| 覆盖区间 | 归档库内最早/最晚 visit（按来源分列）+ 缺口（相邻有数据日之间的空洞） | 「仅覆盖约 90 天」提示由覆盖区间推导，不写死文案数值 |
| 频次榜 | 按 URL / 域名聚合访问**记录数**（并同时给出去重后的条目数，两者单位在输出里标注） | 计数口径先声明条目数/记录数（K21）；并列用显式次排序键（先次数降序，再域名/URL 升序） |
| 时段/星期热力 | 以配置的固定 UTC 偏移换算本地时间后分桶 | 时区口径必须在报告可见；跨日/跨时区样本要有真值用例 |
| 域名集中度 | Top-N 域名占比 + 集中度指标（分子分母都给） | 分母是"全部非私密访问记录数"，报告要写出分母 |
| 会话切分 | 同一来源的访问按时间排序，相邻间隔 **严格大于**配置间隔才切分（恰好等于不切） | 边界用例必测：等于间隔、少 1 秒、多 1 秒 |
| 遗忘的宝藏 | 命中条件（全部取自配置）：①最后一个 visit 距"今天"的天数 **严格大于** 阈值；②总访问次数 ≥ `min_visits`；③访问跨 ≥ `min_distinct_days` 个不同日期；④不在私密/敏感清单 | "今天"由 `now_us` + 配置偏移决定（不读时钟）；命中项必须显示 N 的实际取值；阈值改动要能让真值按定义变化 |
| 下钻 | 每个聚合项带 `evidence`（`visit_id` 列表或可复算谓词） | 引用 id 必须可解析；行数对账（见 K16/M5 的报告门） |

### 验收判据

| 判据 | 断言形态 |
|---|---|
| 数值可下钻 | 报告中每个聚合数字的 `evidence` 引用可在归档库中解析到实际行 |
| 复跑一致 | 同一档案 + 同一配置两次生成，结构化结果逐字段一致 |
| N 改变按定义变化 | 改 N 后命中集合按定义变化，且报告标注了新取值 |
| 边界正确 | 会话间隔三态用例（恰好等于 / 少一秒 / 多一秒）逐条断言 |
| 判定不虚高 | 无适用项 → `not_assessed`，绝不输出成"合规/正常"（K27） |

> **M3 落地形态**（只交数据层；HTML 与渲染门禁归模块⑤）：
>
> - 会话切分的**生产侧唯一定义点**是 `src/browser_history_vault/sessions.py::split_sessions`
>   （K13）；`insight.py` 通过 `insight.split_sessions` 这个引用消费它——**报告层不许有第二份**
>   （`tests/test_sessions_parity.py` 用 AST 断言"生产定义点只有一处"+"报告层用的是同一个函数对象"）。
>   M4 的模块④也复用这一份。
> - 洞察实现在 `src/browser_history_vault/insight.py`：`build_report(rows, *, config, now_us, ...)`
>   → 结构化 dict（`insight-report`），`render_report(document)` → 人读文本；
>   "现在"由 `now_us` 注入（唯一读时钟处在 CLI 编排入口），`--at-us` 显式给出即可复跑对账。
> - **门禁在入口**：`build_report` 第一件事就是 `privacy.keep_visible`，所有聚合只吃可见行——
>   因此"私密记录连统计都不进"在这条链路上是结构性的（会话数 272 而非全量的 288 就是这个差）。
>   需要区分私密/敏感/公开的**遗忘判定**直接吃全量行 + `privacy.classify_host`（条件④把它们排除，
>   命中项必然是公开主机，代码里有二次护栏）。
> - 输出面：`privacy.display_host`（域名列打码）、`privacy.redact_text`（URL / 标题里的主机名回显）、
>   私密主机在呈现层出现即**报错**（fail-closed）。隐私区块只给私密主机的**指纹**与计数，
>   不给主机名。
> - 覆盖区间**按全量行**统计（档案本身覆盖了哪些天，不该因某条记录不可展示而缩水），
>   其余聚合按可见行；两者在文档里分区声明。
> - 报告里的每个榜单项都带 `visit_ids`（可解析 + 行数对账）；`--out-dir` 落 `report.json`。

## 模块④ 主题聚类与研究路径（`cluster`）

### 接口

```python
@dataclass(frozen=True)
class TopicCluster:
    cluster_id: int
    terms: list[str]            # 按权重降序，同权重按词面升序（确定性）
    member_domains: list[str]
    visits: int

@dataclass(frozen=True)
class ResearchPath:
    session_id: int
    steps: list[PathStep]       # 同会话内连续跳转序列（按 visit_time 升序，同刻按 visit_id 升序）
    length: int

def cluster_topics(archive_db: Path, *, config) -> list[TopicCluster]: ...
def research_paths(archive_db: Path, *, config) -> list[ResearchPath]: ...
```

### 判定语义

- **聚类**：纯 Python 轻量 TF-IDF（标题词 + 域名 token），**不引 embedding 模型、不引 sklearn**；
  阈值（`min_df` / `max_features` / `top_terms` / `similarity_threshold`）全部取自配置；
- **确定性**：固定种子（配置）+ **确定性排序**（同分同序：先分值降序，再词面/域名升序）；结果集内不出现集合迭代序与文件枚举序；
- **研究路径**：会话定义**复用模块③的同一实现**（K13，禁止第二份会话切分）；步骤序列按 (时间, visit_id) 排序，同刻访问有稳定次序；
- **路径可下钻**：每个 `PathStep` 携带 `visit_id`。

### 验收判据

| 判据 | 断言形态 |
|---|---|
| 复跑一致 | 同输入两次运行，聚类与路径结果逐字段一致（含固定种子） |
| 同分同序 | 构造分值并列的样本，断言输出次序由显式次排序键决定（打乱输入不变） |
| 阈值可见 | 报告/产物里回显实际使用的阈值取值 |
| 路径真值 | 合成植入的连续跳转序列与真值一致；跨会话不串 |
| 会话口径同源 | 断言模块③④调用同一会话切分函数（结构断言，不是"都调了一个函数"的字面声明） |

> **M4 落地形态**（口径与上面一致，只补充"实现落在哪、边界怎么定的"）：
>
> - 实现落在 `src/browser_history_vault/cluster.py`：`cluster_topics(rows, config=...)`（纯函数，
>   只对**已过门禁**的行工作）→ `build_cluster_document(...)`（**带门禁的入口**：第一步就是
>   `keep_visible_rows`，与 `search_rows` / `build_report` 同构）；数据来自 `storage.visit_view_rows`。
> - **特征面**：标题词（`[^\W_]+` 切分，长度 ≥ 2）+ 域名 token = **站点名（主机最左段）+ 完整主机**。
>   不把主机全拆成标签的理由是实测的：`example` / `test` 这类注册后缀在每个主机里都出现，
>   最普遍的词会把整库并成一簇（"主题"退化成"一个桶"）。`df` 用**文档频率**（去重 URL 条目数），
>   不是访问记录数——否则反复访问同一 URL 会把孤立词抬成高频词，`df < min_df` 必须丢弃这条口径就废了。
> - **合并**：两个词族的成员集 Jaccard ≥ `similarity_threshold` **且**一方包含另一方；只按 Jaccard
>   会链式吞并（实测把 145 个 URL 并成一簇）。分组依据是**词族**，跨域名仍归同一簇。
> - **确定性**：不引随机初始化；保留词按 `idf` 降序 + **词面升序**（同权重必有次键），
>   簇按（访问数降序、首词、最小 URL）编号。产物里回显 `min_df` / `max_features` / `top_terms` /
>   `similarity_threshold` / `random_seed` 与 `session_gap_minutes`。
> - **研究路径**：`research_paths(rows, config=...)` 经 `cluster.split_sessions` 消费 `sessions.py`
>   那一份（**同一函数对象**），步骤 = 会话步骤按 `(visit_time_us, url)` 升序；每步带
>   `visit_id` + 主机（主机只用于输出面打码，不在报告里原样打印）。
> - **隐私**：词表里**与私密/敏感主机同形的词不进词表**，产物只给 `private_shaped_terms_excluded` 计数
>   ——词面本身就是主机名，印出来即泄漏；"掩码成 `***`"会让词表失去意义（`plan/00` D52）。
> - **产物**：`<out-dir>/cluster.json`（机读，`_kind = browser-history-vault/topic-cluster`）+
>   `render_cluster(...)` 人读文本；档案不存在 → **降级（1）+ 零写入**（与 `search` / `report` 同）
> - **本棒不做**：HTML 渲染、embedding / sklearn、`cluster` 的"报告页面"式输出（归 M5 / 明确不做）。

## 模块⑤ 隐私门禁与本地 HTML 报告（`report --html`）

### 接口

```python
@dataclass(frozen=True)
class PrivacyDecision:
    excluded: int        # 私密域名命中而排除的记录数
    masked: int          # 敏感域名命中而打码的记录数

def apply_privacy(records: Iterable[VisitView], *, config) -> tuple[list[VisitView], PrivacyDecision]: ...
def render_html(bundle: InsightBundle, paths: list[ResearchPath], *, meta: ReportMeta) -> str: ...
```

### 判定语义与硬约束

| 约束 | 落地形态 |
|---|---|
| 默认排除私密域名 | 清单只在配置一处定义；**不可静默关闭**（清单为空即报配置错误） |
| 敏感域名打码 | 与"排除"是两回事：敏感域名**保留统计**但显示为掩码；排除的连统计都不进 |
| 报告头部 | 必含：覆盖区间、缺口提示（如"仅覆盖最近约 90 天"）、生效口径块（N / 会话间隔 / 时区 / 阈值实际取值）、归档来源与时间 |
| 首启隐私说明 | 首次运行打印「只读副本 / 本地生成 / 零上传」；标记写**用户主目录**（非仓库），写不进去不算失败（只读环境下每次再念一遍） |
| 零外链 | 渲染出口**常驻断言**：无 `<link>` / 外链 `script`/`img`/`iframe` / `@import` / 外部字体；本项目报告不含"内容链接"，故取**从严档**——`http://`、`https://`、`//` 三种标记一律判红（因此文案、注释、CSS 里都不许出现 `//`，写文案用" / "） |
| 渲染层零判定 | AST 守门：渲染层不 import 引擎/判定模块、不做算术（`BinOp`）、不内联阈值数值；配阳性对照（注入违规必红）与阴性对照（结构性常量/模板渲染必须仍绿） |
| 确定性 | 同一输入双跑，HTML 逐字节一致（无时钟字段、无随机序） |
| 未启用/未探测项 | 独立分区显式写出，不混入结论（"没查"不得读成"查了没问题"） |

### 验收判据

| 判据 | 断言形态 |
|---|---|
| 断网可读 | 报告文件不含任何外部引用；离线打开功能完整（结构 + 资源断言） |
| 私密域名零出现 | 报告与 CSV 中私密域名**一个字符都不出现**（含标题里的域名回显） |
| 覆盖区间与缺口存在 | 报告头结构断言（`coverage` 块 + 缺口列表 + 提示行） |
| 渲染层零判定 | AST 三条断言 + 双对照 |
| 双跑逐字节 | 同输入两次渲染 HTML 字节一致 |
| 打码生效 | 敏感域名以掩码形态出现，且原域名零出现 |

> **M5 落地形态**（本模块已交付，K16 / K25 / K26 / K33）：
>
> - **产物**：`bhvault report --html` → `<out-dir>/report.html`（**单文件**：样式内联、无脚本、
>   无外部资源）+ 原有 `report.json`；`--path-limit N` 控制报告里展示多少条研究路径。
> - **分层**（D54）：`insight.py` / `cluster.py` 出数据 → `report.py` 装配视图（百分比、
>   热力展示等级、SVG 几何、Markdown 强调标记剥离都在这里）→ `render.py` 只做"取字段 → 转义 → 拼接"。
>   渲染层 `import` 面只有标准库 `html`，源码里**零 `BinOp`、零数值字面量**（`render_gate.iter_arithmetic_violations`
>   / `iter_inline_number_violations` 盯着）。
> - **两道出口门**：`report.render_page` 是唯一出口，依次跑 ①AST 三条常驻自检 ②渲染 ③零外链断言
>   ④私密主机零出现断言（判据 = **主机身份**）。任一条红就抛 `report.ReportError`（CLI → 退出码 2），
>   **不静默清洗**。
> - **零外链从严档的实际形态**（D55）：文案 / 注释 / CSS 一律写" / "；**用户数据**里恰好含 `//`
>   （URL 路径、标题）时，转义阶段换成 HTML 实体（显示不变、字面量不出现）——否则真实数据会把
>   报告打成失败。
> - **报告头三块**：`coverage`（区间 + 缺口表 + 由区间推导的提示）/ `effective_config`（N / 会话间隔 /
>   时区 / 聚类阈值 / 起算日 / 配置来源）/ `provenance`（归档库路径 + `archives` 表的来源、profile、
>   归档时刻、扫描与写入条数）。
> - **首启说明**（D57）：`notice.announce()` 在 `report` 首次运行时打印三类声明并把标记写
>   `<用户主目录>/.browser-history-vault/first-run.json`；写不进去只返回 `persisted=False`（命令照常 0）。
> - **确定性**：`report.html` 无时钟字段；同一档案 + 同一配置 + 同一 `--at-us` 两次渲染**逐字节一致**，
>   经 `serialize.write_bytes_atomic` 落盘。
> - **未评估项独立成区**（K27）：`report.unassessed_view` 列出"无数据 / 未评估 / 未验证（其他浏览器格式）"，
>   不与结论混排。

| 扩展 | 预留点 | 前置条件 |
