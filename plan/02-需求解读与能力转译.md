# 02 - 需求解读与能力转译

> **上游依据**：`plan/01-题目文档.md`（题定稿 v1）。本文档把题面的痛点转译成可实现、可断言的能力清单，
> **不复述题面的数值口径**——数值一律以 `config.example.json` 为唯一生效来源（见 `data/README.md` §4）。
> **交付形态**：纯本地 Python CLI + 本地单文件 HTML 报告；无服务器、无 GPU、零网络请求、无账号。

## 1. 痛点 → 能力转译

| # | 痛点（用户视角） | 症状 | 根因（可证） | 能力 | 交付命令 | 断言它的基准/测试 |
|---|---|---|---|---|---|---|
| P1 | 「我的长期历史去哪了？」 | 打开浏览器只能翻到最近三个月 | Chromium 默认删除 90 天前的 visit，且无剩余 visit 时连 URL 行一并删除（`history_backend.h` `kExpireDaysThreshold = 90`；`expire_history_backend.cc`） | **只读快照 + 自有长期档案**：首次运行即把浏览器历史沉淀成自己的库，之后只读自己的库 | `bhvault snapshot` / `bhvault archive` | 原库 `mtime` 不变测试；重复归档幂等测试 |
| P2 | 「我过去到底在做什么？」 | 无从统计频次、时段、集中度 | 浏览器不提供跨月聚合视图 | **行为洞察报告**：频次榜 / 时段热力 / 域名集中度 / 会话切分 | `bhvault report` | 合成真值命中测试（聚合数值与真值一致） |
| P3 | 「哪些是遗忘的宝藏？」 | 想不起以前常看的、后来断掉的内容 | 历史在 90 天窗口里无法表达"长期未访问" | **遗忘的宝藏**：历史高价值但近 N 天未访问（N 取自配置，报告显示实际取值） | `bhvault report`（`forgotten` 区块） | 植入真值命中测试（命中集合与配置 N 一致） |
| P4 | 「我的作息与兴趣怎么变？」 | 只记得大概，拿不出证据 | 无时间序列聚合 | 时段/星期热力（显式时区口径）+ 会话切分 + 主题聚类 | `bhvault report` / `bhvault cluster` | 会话切分真值测试（间隔边界）+ 固定种子复跑一致测试 |
| P5 | 「我当初是怎么找到那篇资料的？」 | 记不住检索—阅读的跳转路径 | 无路径重建能力 | **研究路径**：同会话内连续跳转序列 | `bhvault cluster`（`paths` 区块） | 连续跳转序列真值测试；路径可下钻到具体 visit |
| P6 | 「我想查一条具体记录」 | 浏览器搜索太弱、不能按域名/区间收窄 | — | **归档检索**：URL / 标题 / 域名 / 时间范围 + CSV 导出，中文走字 n-gram 兜底 | `bhvault search` | 断网查询可用测试 + 排序键确定性测试 |
| P7 | 「这东西会不会把我的浏览记录传出去？」 | 同类工具常有联网组件 | — | **隐私门禁**：只读副本、默认排除私密域名、敏感域名打码、单文件 HTML 零外链、零网络请求 | `bhvault report --html` | 零外链出口断言 + 私密域名零出现断言 + socket 拦截测试 |
| P8 | 「我看到的是一部分还是全部？」 | 报告不说明数据边界，容易误读 | 90 天窗口天然残缺 | **覆盖区间与缺口如实显示** | `bhvault status` / 报告头部 | 区间与「仅覆盖约 90 天」提示存在性测试 |

## 3. 非功能需求（NFR）

| NFR | 要求 | 落地方式（本版本的证据） |
|---|---|---|
| NFR-1 只读 | 任何情况下不以写模式打开用户浏览器原库 | 快照只读副本；`snapshot` 的 DoD 含原库 `mtime` 不变断言 |
| NFR-2 零网络 | 不发起任何网络请求，不内嵌远程字体/脚本/图片 | 静态 import 守门（AST，逐形态探针）+ 运行时 socket 拦截；报告渲染出口常驻零外链断言 |
| NFR-3 确定性 | 同一输入 + 同一配置 → 同一输出；固定随机种子、确定性排序、不读系统时钟 | 机读产物统一确定性序列化；`bhvault config` 双跑逐字节一致（已有测试）；后续产物逐个锁"同输入双跑" |
| NFR-4 口径单一 | 数值只在配置一处定义，代码零默认值 | dataclass 无默认值的结构断言 + "改配置输出即变"的行为断言 |
| NFR-5 可下钻 | 每个聚合数字可追溯到原始访问行 | 报告含引用 id；行数对账与引用可解析断言（M5） |
| NFR-6 可复跑 | 合成数据 + 植入真值 + 固定种子，任何人一键复跑 | 生成器 `--check` 位级一致；基准套件（M1 起） |
| NFR-7 兼容 | Python 3.8+；Windows / Linux 双平台 | 本机双通道（3.8.8 / 3.12.10）全量测试；CI 四矩阵（{windows,ubuntu}×{3.8,3.12}） |
| NFR-8 零依赖 | 运行时零第三方依赖（stdlib only） | `dependencies = []`；干净 venv 按 README 安装后全量测试 |
| NFR-9 隐私 | 真实浏览历史永不入仓；提交元数据用 noreply 邮箱 | `.gitignore` 封死 `History*` / `*.db` / 报告产物；发布期脱敏扫描 |
| NFR-10 可维护 | 模块边界清晰；口径与判定单点实现 | 本目录 plan/03–04 的 K 清单；单点实现 + 扫描断言 |
| NFR-11 诚实 | 措辞与审计范围对齐；未验证项不用确定语气 | README「局限与已知问题」节；`data/README.md` 三态列；发布留档只写实测到的 |

## 4. 边界与非目标

题面 §6 已定稿切割线，此处只列**工程上会被反复试探**的四条（完整清单以 `plan/01-题目文档.md` §6 为准）：

1. **不写浏览器原库**——任何情况不得以写模式打开用户浏览器库（只读副本是红线，不是建议）；
2. **不做书签整理、不做失效链接清理、不做页面内容存档**——收藏是「打算以后看」，历史是「过去在做什么」，不是同一个问题；
3. **不做云同步/账号体系、不上传任何数据**——零网络请求是硬约束；
4. **不做「隐私评分」**——避免用单一分数误导用户对隐私状态的判断。

## 5. 退出码语义

退出码在代码里只有一处定义（`src/browser_history_vault/exit_codes.py`），README 与本文档只引用语义、不复述数字：

| 语义 | 含义 | 典型场景 |
|---|---|---|
| 完成 | 命令按既定语义跑完，无降级 | `config` / `selftest` 全绿 |
| 降级完成 | 跑完了，但存在需要人注意的事实 | 档案覆盖区间有缺口；selftest 有 FAIL 项 |
| 输入或用法不可用 | 缺文件、坏格式、未知命令、参数错误 | `--config` 指向不存在的文件（且**不回落其他来源**） |
| 阶段未就绪 | 该能力尚未在本版本交付 | `snapshot` 等六个命令（显式拒绝，零写入） |

**两条纪律**：

- **退出码会随能力解锁而退役**：某模块落地后，它的"未就绪"条目要**整项退役**（五处同步，见 `plan/03` §11）；否则文档说一套、代码做一套；
- **面向用户的文案不引用里程碑编号**：用户看不到计划，只看得到承诺——"planned for M3" 这类句子会过期成谎言（已有测试断言未就绪文案里不出现 M1–M6）。

## 6. 用户旅程（首期目标态）

```
① 复制配置并按自己的情况改（会话间隔 / N / 私密域名 / 时区）
        ↓
② bhvault snapshot          只读副本；浏览器运行中也行；原库 mtime 不变
        ↓
③ bhvault archive           增量合并进自有档案；重复跑不产生重复行
        ↓
④ bhvault status            看覆盖区间与缺口（"仅覆盖约 90 天"如实提示）
        ↓
⑤ bhvault search / report / cluster
        ↓
⑥ 单文件 HTML 报告（零外链、可断网打开、可归档转发）
```

关键性质：**②③ 是不可逆数据链的唯一入口**——错过今天，90 天前的数据就永久消失了。因此工具的
第一价值不是"分析得多好"，而是**从第一次运行起就在替用户抢救数据**。
