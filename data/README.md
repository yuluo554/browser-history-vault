## 3. 合成数据纪律（M1 起执行）

### 3.1 假域名白名单

- 合成 History 库中的 URL **只允许**使用以下保留域名：`example.invalid`、`example.test`、`example.com` 的 `example.*` 子域，以及 RFC 2606 保留域。
- 禁止使用任何真实站点域名、真实用户名、真实邮箱。
- 合成标题使用中性占位文本（如「示例文章 A-001」），不用真实人名/机构名。

### 3.2 植入真值

合成库必须**程序化植入已知真值**，并在 `manifest` 中显式登记：

| 真值类型 | 植入方式 | 应验证 |
|---|---|---|
| 访问序列 | 指定时间点的 visit 序列 | 会话切分（30 分钟边界：恰好 30 分钟、29 分 59 秒、30 分 1 秒） |
| 遗忘的宝藏 | 指定 URL 最后一次访问距今超过 N 天 | 命中集合与配置 N 一致 |
| 时段/星期热力 | 指定时区的访问分布 | 聚合数值与真值一致 |
| 域名集中度 | 指定域名的访问比例 | 比例与真值一致 |
| 主题聚类 | 指定标题词族的分布 | 固定种子下分组结果稳定 |
| 研究路径 | 同会话内连续跳转序列 | 路径序列与真值一致 |
| 中文检索 | 含中文标题的样本 | 字 n-gram 查询命中 |
| 私密域名 | 清单内域名的访问记录 | 报告与导出中零出现 |

**生成纪律**：生成脚本必须支持 `--check` 复跑并位级一致（固定种子、固定字段顺序）；合成库本身可入仓（假域名），但**真实历史库永不入仓**。

### 3.3 时间与纪元

- 合成库时间戳一律按 **1601 纪元微秒**写入（与 Chromium 一致），生成器内部用显式转换函数，禁止手写魔数；
- 测试断言使用相对时间（如「最后访问距归档日 N-1 天」），避免写死日历日期。

## 4. 数值口径纪律（单点定义）

以下数值**只在配置文件一处定义**（建议 `config.toml` 或 `config.json`，M1 冻结），代码、报告、文档一律引用该处，禁止第二份手写口径：

| 口径 | 值 | 说明 |
|---|---|---|
| 会话切分间隔 | **30 分钟** | 相邻访问间隔超过该值即切分会话 |
| 「遗忘的宝藏」未访问天数 N | 配置项 | 报告中显示实际取值；文档不写死第二份 |
| 私密域名清单 | 配置项（默认清单） | 默认排除；用户可增删，但不可静默关闭 |
| 聚类阈值 / 相似度阈值 | 配置项 | 固定后进报告可见 |
| 时区口径 | 配置项 | 默认本地时区；热力与星期统计均以此为准 |
| 随机种子 | 配置项（固定值） | 聚类等含随机初始化步骤时使用 |
| 字 n-gram 的 n | 配置项 | 中文检索兜底 |

**纪律**：报告、README、CLI `--help` 中的数值不得各写一份；文档需要举例时写「以配置为准」。

## 5. 隐私与提交纪律

- 真实浏览历史、真实 `History` / `-wal` / `-shm` 文件**永不入仓**；
- 归档库（`*.db`）、导出 CSV、生成的 HTML 报告均默认不入仓；
- 提交元数据使用 GitHub noreply 邮箱；发布前扫描全部历史提交与 tag tagger 邮箱；
- 报告中敏感域名自动打码，私密域名零出现；
- 零网络请求：代码中不得存在 HTTP 客户端调用路径（测试以静态扫描 + 断网运行双证）。
